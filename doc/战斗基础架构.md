# 战斗基础架构

## 当前临时方案

当前优先验证 PIE 效果，因此保留 `ACS` 作为主角兼容宿主，不立即重构既有继承链：

```text
ACS : ACharacter, IAbilitySystemInterface
 -> CombatAbilitySystemComponent
 -> CombatAttributeSet
 -> CombatScriptBridge
 -> CommonAtk GAS Abilities

ACombatMonsterCharacter : ACS
```

`ACombatMonsterCharacter` 复用同一套 GAS、Ability 和 Bridge，但默认关闭玩家输入。怪物后续可以由 AI 或 AngelScript 直接调用 `RequestCommonAtkInput()`，不需要复制一套战斗逻辑。

角色配置暂时使用 `ACS` 上的蓝图可编辑字段，后续迁移到 DataAsset 时不改变 CommonAtk 接口：

```text
CharacterId
SkeletonId
CombatProfileId
AbilitySetId
FactionId
```

## C++/GAS 宿主

现有组件：

```text
UCombatAbilitySystemComponent
UCombatAttributeSet
UCombatScriptBridge
UScriptDrivenGameplayAbility
```

职责：

- 初始化 ASC 和 AttributeSet。
- 授予并管理 CommonAtk 三段 Ability。
- 管理脚本 Bridge 生命周期和阶段 Gameplay Tag。
- 在没有动画资源时输出播放动画日志。
- 拦截攻击期间的移动，并在 Ending 阶段恢复移动。

## AngelScript 可编辑层

脚本目录：

```text
Demo/Script/Combat/
```

当前阶段时长、动作编号和 Combo 规则仍通过 Bridge 的可重载接口调整。脚本层不直接操作裸 ASC、AttributeSet 或 Health。

## 当前已验证接口

```text
RequestCommonAtkInput()
ActivateCommonAttackIndex(AttackIndex)
CanStartAttack(AttackId)
GetPhaseDuration(AttackIndex, PhaseIndex)
PlayAttackAnimation(AttackId, AnimationId)
CanMove()
```

## 生命周期

```text
BeginPlay
 -> 输出 CharacterId/Faction/Profile/AbilitySet
 -> 初始化 ASC 和 AttributeSet
 -> 创建 CombatScriptBridge
 -> 授予 CommonAtk_01/02/03
 -> Idle
```

攻击流程：

```text
鼠标左键或脚本请求
 -> CommonAtk_01
 -> SingleLaunch
 -> AfterLaunch
 -> Combo
 -> CommonAtk_02 / CommonAtk_03 或 Ending
 -> Idle
```

## 后续迁移

正式方案再拆出 `ACombatCharacterBase` 和 DataAsset 配置。迁移时保留 `RequestCommonAtkInput()`、`CanMove()` 和 Bridge 接口，避免重写 Combo 脚本。
