# 主角与怪物蓝图及资源规范

## 当前临时实现

为了先看到运行效果，当前采用兼容方案：

```text
ACS : ACharacter
 -> 主角 BP：BP_Player_C0000

ACombatMonsterCharacter : ACS
 -> 怪物 BP：BP_Monster_Test
```

正式架构后再把公共组件迁移到 `ACombatCharacterBase`。CommonAtk、GAS 和 AngelScript 接口保持不变。

## 蓝图字段

`ACS` 暂时暴露以下字段，直接在 BP Class Defaults 中修改：

```text
CharacterId
SkeletonId
CombatProfileId
AbilitySetId
FactionId
bEnablePlayerCombatInput
```

当前默认值：

| 蓝图 | CharacterId | FactionId | 输入 |
|---|---|---|---|
| `BP_Player_C0000` | `C0000` | `Faction.Player` | 开启 |
| `BP_Monster_Test` | `TestMonster` | `Faction.Enemy` | 关闭 |

BeginPlay 会打印这些字段，方便在 Output Log 核对装配结果。

## 输入和攻击

主角：

```text
鼠标左键 -> CommonAtk -> CommonAtk_01/02/03
W/A/S/D -> 移动
```

怪物不绑定玩家输入。AI 或 AngelScript 通过以下接口请求攻击：

```text
RequestCommonAtkInput()
ActivateCommonAttackIndex(AttackIndex)
```

当前无真实动画，攻击开始时输出：

```text
[Combat] CommonAtk_01 PlayAnimation AttackId=CommonAtk_01 AnimationId=002000
```

阶段由脚本/C++ Bridge 的临时计时器推进：

```text
SingleLaunch -> AfterLaunch -> Combo -> Ending
```

## 蓝图边界

允许：

- 配置 Mesh、AnimBP、Physics Asset。
- 配置角色身份、阵营、CombatProfile 和 AbilitySet 占位字段。
- 配置移动、碰撞和 AI 装配参数。

禁止：

- 在 Event Graph 中复制 Combo 状态机。
- 直接修改 Health 或执行伤害公式。
- 直接调用裸 ASC 的内部接口。
- 在蓝图中手写 Sweep 命中和受击规则。

## 测试步骤

1. 打开 `BattleMap`，确认 `TMP_Player_C0000` 和 `TMP_Monster_Test` 存在。
2. PIE 后按一次鼠标左键，观察 `CommonAtk_01` 和 `AnimationId=002000`。
3. 在 Combo 阶段再次按左键，观察 `CommonAtk_02`、`CommonAtk_03`。
4. 修改 `BP_Player_C0000` 的 `CombatProfileId`，重新 PIE，观察 BeginPlay 日志。
5. 通过 AI/脚本调用 `TMP_Monster_Test.RequestCommonAtkInput()`，确认怪物复用同一套 Ability。

## 后续迁移

当进入正式资源阶段：

1. 新增 `ACombatCharacterBase`，承载公共 ASC、AttributeSet 和 Bridge。
2. 把上述 `FName` 占位字段迁移到 `DA_CharacterProfile`、`DA_CombatProfile` 和 `DA_AbilitySet`。
3. 用真实 Skeleton、Animation Blueprint、Montage 和 AnimNotify 替换临时计时器。
4. 保留 `CommonAtk_01/02/03` 业务 ID，不把 Elden Ring 原始动作文件名直接当作 Combo 状态名。
