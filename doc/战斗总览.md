# 战斗系统总览

## 目标

建立一个由 AngelScript 编辑战斗规则、由 C++ 和 GAS 执行底层操作的战斗框架。修改 Combo、伤害公式、动作选择和打断规则时，不需要重新编译 C++。

## 分层职责

### 角色装配层

当前临时蓝图规则：

```text
ACS                         主角兼容宿主，默认响应玩家输入
ACombatMonsterCharacter     怪物临时宿主，默认不响应玩家输入
```

蓝图只配置 Mesh、AnimBP、Physics Asset 和角色身份字段。Combo、伤害、受击和状态机不写在 Event Graph 中。

### AngelScript 逻辑层

- `CommonAtkAbilityGroup`：普通攻击能力组和动作选择。
- `ComboController`：Combo 状态、输入缓存和段数推进。
- `DamagePolicy`：伤害公式和目标修正。
- `HitPolicy`：命中目标过滤和多目标规则。
- `ReactionPolicy`：受击、硬直、死亡和打断规则。

### C++/GAS 执行层

- `AbilitySystemComponent`：能力、标签、效果和网络权限。
- `CombatAttributeSet`：Health、Defense、AttackPower、Poise。
- `CombatScriptBridge`：向脚本暴露安全调用接口。
- 碰撞查询：执行 Sweep、过滤物理碰撞并返回命中结果。
- 动画执行：播放 Montage、跳转 Section、派发 Notify。
- GAS 应用：校验并提交 Gameplay Effect。

## 数据流

```text
输入
 -> AS CommonAtkAbilityGroup
 -> AS ComboController
 -> C++ PlayMontage
 -> AnimNotify AttackHit
 -> C++ Sweep
 -> AS HitPolicy
 -> AS DamagePolicy
 -> C++/GAS ApplyGameplayEffect
 -> AttributeSet.Health / Poise
 -> AS ReactionPolicy
```

## 不允许跨层的行为

- AngelScript 不直接写入目标 Health。
- C++ 不包含具体的三段 Combo 分支。
- 命中查询不在 AngelScript 中手写物理碰撞。
- 伤害公式不散落在多个 C++ Ability 类中。
- UnLua 不负责战斗核心状态。

## 第一版边界

- 单角色、单武器、三段普通攻击。
- 服务器权威接口保留，但优先完成本地 PIE。
- 当前先不执行真实伤害和命中 Sweep，只输出攻击阶段和动画占位日志。
- `CombatAttributeSet` 已作为底层入口保留，伤害和命中在后续模块接入。
- 先用临时角色宿主验证输入、Ability 生命周期和 Combo，再迁移到 DataAsset 驱动的正式角色基类。
